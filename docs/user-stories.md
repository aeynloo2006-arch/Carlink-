۱. مقدمه

۱.۱ هدف سند

این سند داستان‌های کاربر (User Stories) پروژه CarLink را تعریف می‌کند.

هر داستان کاربر از دیدگاه یکی از کاربران نوشته شده و نیاز، هدف و ارزش مورد انتظار او را مشخص می‌کند.

۱.۲ قالب User Story

هر داستان کاربر با قالب زیر نوشته می‌شود:

«به‌عنوان [نقش]، می‌خواهم [کاری را انجام دهم]، تا [به هدف موردنظر برسم].»

۱.۳ معیارهای INVEST

- Independent: مستقل
- Negotiable: قابل مذاکره
- Valuable: ارزشمند
- Estimable: قابل تخمین
- Small: کوچک
- Testable: قابل آزمایش

۱.۴ اولویت‌بندی MoSCoW

- Must: ضروری
- Should: مهم
- Could: اختیاری
- Won't: خارج از محدوده نسخه فعلی

۶. معیارهای پذیرش نمونه (Acceptance Criteria)

US-02 — جست‌وجوی تعمیرکاران

به‌عنوان: مشتری

می‌خواهم: تعمیرکاران را جست‌وجو و فیلتر کنم

تا: متخصص مناسب را پیدا کنم.

معیار پذیرش:

- [ ] امکان ثبت برند و مدل خودرو وجود داشته باشد.
- [ ] امکان جست‌وجو بر اساس تخصص تعمیرکار وجود داشته باشد.
- [ ] امکان فیلتر بر اساس موقعیت مکانی وجود داشته باشد.
- [ ] نتایج مرتبط با جست‌وجو نمایش داده شوند.
- [ ] در صورت نبود نتیجه، پیام مناسبی نمایش داده شود.

US-03 — مشاهده و مقایسه تعمیرکاران

به‌عنوان: مشتری

می‌خواهم: اطلاعات و مشخصات تعمیرکاران را مقایسه کنم

تا: انتخاب بهتری داشته باشم.

معیار پذیرش:

- [ ] پروفایل تعمیرکار قابل مشاهده باشد.
- [ ] تخصص و سابقه کاری نمایش داده شود.
- [ ] امتیاز و نظرات مشتریان نمایش داده شوند.
- [ ] امکان انتخاب چند تعمیرکار برای مقایسه وجود داشته باشد.
- [ ] فاصله و زمان انتظار در صورت ثبت اطلاعات نمایش داده شود.

US-07 — تأیید هزینه تعمیر

به‌عنوان: مشتری

می‌خواهم: هزینه پیشنهادی تعمیر را تأیید یا رد کنم

تا: تعمیر بدون موافقت من آغاز نشود.

معیار پذیرش:

- [ ] تعمیرکار پس از عیب‌یابی بتواند هزینه را ثبت کند.
- [ ] مبلغ پیشنهادی به مشتری نمایش داده شود.
- [ ] مشتری بتواند هزینه را تأیید یا رد کند.
- [ ] وضعیت تأیید مشتری ثبت شود.
- [ ] شروع تعمیر به تأیید مشتری وابسته باشد.

US-08 — ثبت درخواست امداد و محاسبه هزینه حمل

به‌عنوان: مشتری

می‌خواهم: درخواست امداد خودرو ثبت کنم و هزینه حمل را مشاهده کنم

تا: از مبلغ تقریبی خدمات مطلع باشم.

معیار پذیرش:

- [ ] امکان انتخاب مبدأ و مقصد وجود داشته باشد.
- [ ] نوع و وضعیت خودرو قابل انتخاب باشد.
- [ ] فاصله مسیر محاسبه شود.
- [ ] هزینه تخمینی حمل پیش از ثبت درخواست نمایش داده شود.
- [ ] امکان ثبت نهایی درخواست وجود داشته باشد.

US-11 — مدیریت تعمیرگاه

به‌عنوان: صاحب تعمیرگاه

می‌خواهم: اطلاعات و درخواست‌های تعمیرگاه را مدیریت کنم

تا: خدمات خود را بهتر ارائه دهم.

معیار پذیرش:

- [ ] امکان ایجاد و ویرایش پروفایل وجود داشته باشد.
- [ ] درخواست‌های مشتریان نمایش داده شوند.
- [ ] امکان مدیریت نوبت‌ها وجود داشته باشد.
- [ ] وضعیت باز یا بسته بودن و شلوغی قابل به‌روزرسانی باشد.
- [ ] امکان اعلام هزینه پس از عیب‌یابی وجود داشته باشد.

US-12 — مدیریت درخواست‌های امداد

به‌عنوان: امدادگر

می‌خواهم: درخواست‌های نزدیک را مشاهده و مدیریت کنم

تا: مأموریت‌های مناسب را انتخاب کنم.

معیار پذیرش:

- [ ] درخواست‌های جدید نمایش داده شوند.
- [ ] اطلاعات مبدأ، مقصد و نوع خودرو مشخص باشند.
- [ ] امکان قبول یا رد درخواست وجود داشته باشد.
- [ ] وضعیت فعالیت امدادگر قابل تغییر باشد.
- [ ] وضعیت مأموریت قابل به‌روزرسانی باشد.

US-13 — مدیریت کاربران و شکایات

به‌عنوان: مدیر سامانه

می‌خواهم: اطلاعات کاربران، نظرات و شکایات را بررسی کنم

تا: کیفیت خدمات حفظ شود.

معیار پذیرش:

- [ ] اطلاعات کاربران قابل مشاهده باشد.
- [ ] نظرات و گزارش‌های ثبت‌شده قابل بررسی باشند.
- [ ] شکایات کاربران نمایش داده شوند.
- [ ] امکان ثبت نتیجه رسیدگی وجود داشته باشد.
- [ ] گزارش عملکرد خدمات قابل مشاهده باشد.

US-14 — مدیریت دسترسی و تأیید مدارک

به‌عنوان: مدیر سیستم

می‌خواهم: دسترسی کاربران و مدارک ارائه‌دهندگان خدمات را مدیریت کنم

تا: امنیت و اعتبار سامانه حفظ شود.

معیار پذیرش:

- [ ] امکان مدیریت نقش‌های کاربری وجود داشته باشد.
- [ ] امکان فعال یا غیرفعال کردن حساب‌ها وجود داشته باشد.
- [ ] مدارک تعمیرکاران و امدادگران قابل مشاهده باشند.
- [ ] امکان تأیید یا رد مدارک وجود داشته باشد.
- [ ] سطح دسترسی کاربران مطابق نقش آن‌ها کنترل شود.

نتیجه‌گیری

در این سند، ۱۵ داستان کاربر برای پروژه CarLink تعریف شده است. این داستان‌ها نیازهای اصلی مشتریان، تعمیرکاران، امدادگران و مدیران سامانه را پوشش می‌دهند.

این مجموعه می‌تواند مبنایی برای تهیه موارد کاربرد (Use Cases)، نیازمندی‌های عملکردی و طراحی جریان‌های کاربری (User Flows) در مراحل بعدی پروژه باشد.
